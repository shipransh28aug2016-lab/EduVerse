# Performance audit

Measured 2026-11-11 with Chromium (Playwright) on the build environment's CPU, software WebGL, local static server. Reproduce with `node tests/perf-size.cjs`, `node tests/perf-throttle.cjs`, `node tests/lab-smoke.cjs`. **Emulation, not hardware:** no physical Android phone, GPU or real mobile network was available. Treat the throttled numbers as indicative.

## 2. Degraded conditions (emulated)

Network 400 kbit/s with 400 ms round trip, CPU slowed 6×, server compressing like GitHub Pages, cold cache, service worker blocked:

| Page | Seconds until usable | Slider input → redraw |
|---|---|---|
| Home | 3.8 | – |
| T09 Price Puzzle | 5.3 | 14.8 ms |
| T11 Ecosystems | 5.8 | 9.0 ms |
| T16 Finance | 6.1 | 5.1 ms |

Interaction stays under one 60 fps frame (16 ms) even at 6× CPU slowdown. The cold-load figure is dominated by the 400 ms round trip repeated over the chain `index.html → main.js → imports → data`. Total transfer for a lab page (about 80 KB gzip) is about 1.7 s of bandwidth at this speed.

On normal-speed desktop Chromium, themes reach an interactive lab in 90–365 ms, and a slider event redraws in 0.2–2.1 ms (mean of 20 events). JS heap read 10 MB for every page (the browser reports this counter in coarse steps, so treat it as "no leak visible", not a precise figure).

## 3. Offline

A service worker (`sw.js`, generated by `tools/build-sw.mjs`) precaches the 62 app files and refreshes them in the background (stale-while-revalidate). Test: visit once online, switch the network off, reload the home page, open T16, move a slider. All succeeded (63 cached entries). Not offline: a first visit, and the three.js module until the 3D tab has been opened once online. After a deployment, a returning user receives the new version on their second load.

Limitations: the service worker needs `https://` or `localhost`; it is skipped on `file://`. Re-run `node tools/build-sw.mjs` after adding files, otherwise new files are fetched from the network (and cached then) rather than precached.

## 4. Responsive layout

At 360 px width (touch emulation) all 16 theme pages have zero horizontal overflow, and in the labs every chip, option and button is at least 44 px tall (`tests/a11y-smoke.cjs`). Graphics are `viewBox` SVG and scale with the column.

## 5. Not measured

- Frame rate on a real Android GPU (the 3D tab was only exercised with software rendering; it renders on demand, with a low-graphics mode and a no-WebGL fallback).
- Memory on a 2 GB phone; long sessions.
- Real-network time to first interaction (CDN, TLS, HTTP/2 push are outside the emulation).
- Battery and thermal behaviour.

## 6. Recommendations

1. Add `<link rel="modulepreload">` for `src/main.js` dependencies, or bundle the home route's modules into one file, to cut the sequential round trips on slow links.
2. Ship `curriculum.json` and `ui.js` split per theme if the home payload must go below 40 KB.
3. If 3D landform or ocean-relief scenes are added: compress meshes (Draco/meshopt), cap triangles per scene, add level-of-detail, and keep each scene under 500 KB.
4. Measure on two real Android devices (one low-end, with 2 GB RAM) before classroom rollout and record the figures here.
